# Что именно появится: разбор по возможностям

Дополнение к [ROADMAP](ROADMAP.md) (когда) и [SPRINT-1](SPRINT-1.md) (как).
Здесь — **что**: вход, выход и признак готовности каждой возможности.

Порядок не случаен: каждая следующая опирается на предыдущую, и каждую можно
выкатить отдельно.

---

## I квартал. Всё то же самое, но доступное агенту

### `make_icons` — набор иконок из чего угодно

| | |
|---|---|
| **Вход** | строка SVG · символ эмодзи · текст плюс шрифт · путь к картинке (PNG/SVG/WebP) |
| **Настройки** | форма (квадрат, круг, скруглённый с радиусом) · фон (сплошной, градиент, прозрачный) · отступ · рамка · обводка текста |
| **Выход** | `favicon.ico` (16+32+48), `favicon-16/32.png`, `apple-touch-icon.png` (180), `android-chrome-192/512.png`, maskable-варианты, `favicon.svg`, тёмный вариант, `safari-pinned-tab.svg`, `site.webmanifest`, `browserconfig.xml` |
| **Плюс текстом** | готовый блок `<link>` для `<head>` и вариант `app/icon.tsx` для Next.js |
| **Готово, когда** | агент вызывает инструмент, получает файлы в каталоге проекта и вставляет блок в разметку без правок руками |

**Почему это ядро.** Модель рисует SVG за секунду, но `favicon.ico` из трёх
изображений не соберёт и безопасную зону maskable не посчитает. Здесь
инструмент делает то, где модель бессильна.

### `make_og_image` — карточка для мессенджеров, первая версия

| | |
|---|---|
| **Вход** | иконка или логотип плюс заголовок |
| **Выход** | `og-image.png` 1200×630 и мета-теги `og:image`, `twitter:image` |
| **Готово, когда** | ссылка на сайт в Телеграме разворачивается картинкой, а не серым прямоугольником |

### `audit_head` — что у сайта не хватает

| | |
|---|---|
| **Вход** | адрес сайта или строка HTML |
| **Выход** | список по разделам: иконки, PWA, соцсети, манифест — что есть, чего нет, что сомнительно |
| **Готово, когда** | разбор чужого сайта даёт тот же список, что и браузерная версия |

**Намеренно только диагностика.** Инструмент не правит чужую разметку сам:
решение, что добавлять, остаётся за человеком или за агентом, который его
позовёт.

## II квартал. Карточки соцсетей как отдельная работа

### Раскладки карточек

Не одна картинка из иконки, а **шаблоны под разное содержание**:

| Раскладка | Для чего |
|---|---|
| Заголовок по центру | главная страница, лендинг |
| Логотип слева, текст справа | статья, запись блога |
| Цитата крупно | материал с сильной фразой |
| Заголовок плюс подпись и метка раздела | документация, каталог |

**Вход:** заголовок, подпись, метка, логотип, фирменный цвет.
**Выход:** PNG 1200×630 плюс блок мета-тегов.
**Готово, когда** три страницы одного сайта получают три разные карточки из
одного вызова, и они узнаваемо одной семьи.

### Карточки пачкой — из карты сайта

| | |
|---|---|
| **Вход** | `sitemap.xml` или список адресов |
| **Что делает** | берёт у каждой страницы `title` и описание, рисует карточку, складывает файлы и готовые теги |
| **Готово, когда** | сайт на двадцать страниц получает двадцать карточек одной командой |

**Зачем именно так.** Карточка нужна каждой странице, а рисуют её обычно один
раз для главной — просто потому, что вручную это двадцать заходов в редактор.

### Разбор расширяется

К иконкам добавляются проверки: `og:` и `twitter:` полностью, размеры
картинки, `robots.txt`, наличие `sitemap.xml`, язык страницы, `theme-color`.

**Готово, когда** на своём сайте разбор находит то, о чём не знали, и список
исправим за один заход.

## III квартал. Фирменный стиль из одного входа

### Цветовые токены

| | |
|---|---|
| **Вход** | один фирменный цвет (и при желании второй, акцентный) |
| **Выход** | переменные CSS для светлой и тёмной темы: фон, поверхность, текст, приглушённый текст, граница, акцент, состояния |
| **Правило** | каждая пара «текст на фоне» проверяется на контраст — проверка уже написана; пара, не проходящая по нормам, не выдаётся, а подправляется по светлоте |
| **Дополнительно** | тот же набор в виде куска конфигурации Tailwind |
| **Готово, когда** | из одного цвета получается тема, в которой ни одна пара не нарушает нормы доступности |

### Оптимизация картинок

| | |
|---|---|
| **Вход** | PNG, JPEG, WebP |
| **Выход** | WebP и AVIF с выбором качества, при необходимости — несколько размеров и готовый `<picture>` |
| **Где считается** | в браузере; для агента — тем же ядром в Node |
| **Готово, когда** | картинка для статьи готовится без захода на сторонние сервисы |

### Наборы проекта

| | |
|---|---|
| **Что это** | сохранённый набор «цвет, шрифт, форма, отступы» под конкретный сайт |
| **Зачем** | у семейства сайтов одного заказчика вид держится сам, а не восстанавливается по памяти |
| **Выход** | файл набора в репозитории проекта; агент подхватывает его и не спрашивает настроек |
| **Готово, когда** | второй сайт того же заказчика собирается без единого вопроса о цветах |

## IV квартал. Форма, а не возможности

Новых возможностей не планируется намеренно — квартал на то, чтобы решить
судьбу по факту сделанного:

- **вызов из командной строки** рядом с MCP, если окажется, что удобнее звать
  из сборки, а не из разговора;
- **страница с описанием** — не реклама, а место, куда сослаться;
- **имя** — менять, если проект вышел за иконки.

## Что в этот список не войдёт

**Художественная обработка.** Обрезка по маске — да, подбор фильтров и
ретушь — нет. Граница проходит по слову «детерминированно»: одинаковый вход
даёт одинаковый выход, и результат можно проверить сравнением.

**Генерация логотипа.** Это работа модели, а не инструмента. Инструмент
принимает готовый SVG и раскладывает его правильно.

**Хранилище.** Ни учётных записей, ни чужих файлов на сервере — иначе исчезает
то единственное, что даёт приложению право на существование: оно работает без
сети и ничего никуда не отправляет.
