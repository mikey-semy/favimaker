## Что действительно стоит добавить

### 1. MCP-сервер — единственное настоящее расширение

Сейчас иконки делает человек в браузере. В работе же они нужны агенту: заводим
проект из шаблона — и на этом шаге хочется «сделай набор иконок из 🦊 и впиши
ссылки в head», без переключения на вкладку.

**Осуществимость проверена по коду.** `lib/renderer.ts` — чистая функция:
конфигурация → canvas, на весь файл одно обращение к `document`. Значит он
переносится в Node почти как есть, если подставить `@napi-rs/canvas` вместо
браузерного canvas.

Разложение:

| Что | Куда |
|---|---|
| `renderer`, `ico`, `manifest`, `export`, `types`, `og-renderer`, `splash-renderer` | общее ядро, без React и DOM |
| адаптер canvas | два: браузерный и `@napi-rs/canvas` |
| MCP-инструменты | `make_icons`, `make_og_image`, `audit_head` |

Инструменты пишут файлы прямо в каталог проекта и возвращают готовый кусок для
`<head>` — агенту не нужно передавать двоичные данные через протокол.

### 2. Сказать людям, что он есть

Это **не маркетинг ради маркетинга**, а следствие факта: привычные сервисы
отсюда не открываются, и человек, которому нужны иконки, сейчас просто не
находит замены. Тут выигрывает не тот, у кого больше кнопок, а тот, кто
доступен.

Дёшево и по делу: заметка на Хабр с честным заголовком «генератор фавиконок,
который открывается из России», упоминание в тематических каналах, и чтобы сам
сайт первым экраном говорил, чем он отличается.

### 3. Мелкие пробелы, которые к месту

- **Оптимизация картинок**: перегнать PNG/JPEG в WebP/AVIF с выбором качества —
  та же браузерная кухня, та же нужда, тот же «не загружать файл никуда».
- **`robots.txt` и заготовка `sitemap.xml`** — мелочь, которую каждый раз пишут
  заново.
- **Цветовые токены**: из фирменного цвета — переменные CSS для светлой и
  тёмной темы. Проверка контраста для этого уже есть.

## Чего делать не стоит

**Не превращать в «комбайн для всего веба».** Связь между частями должна быть
понятной: всё, что попадает в `<head>` нового сайта, — да; редактор изображений
общего назначения — нет.

**Не заводить серверную часть.** Отсутствие сервера — не упрощение, а свойство:
картинка не уходит с машины, приложение работает офлайн и не зависит от того,
пропускают ли трафик. Ровно это и делает его доступным там, где недоступны
другие.
