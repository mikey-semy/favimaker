# План на год: сентябрь 2026 → сентябрь 2027

Название `favimaker` — рабочее. Оно описывает сегодняшний день (иконки), а не
то, куда идёт проект, поэтому план построен вокруг сути, а не вокруг имени.

## Суть, если назвать одним предложением

**Готовые ресурсы для нового сайта — иконки, карточки соцсетей, манифесты,
темы, — которые собираются детерминированно, в браузере или по вызову агента.**

Из этой формулировки видно и границу, и куда можно расти: всё, что нужно сайту
на старте и делается по правилам, а не по вдохновению.

## Что уже есть (сентябрь 2026)

Иконки во всех видах, maskable, `safari-pinned-tab`, тёмный фавикон, экраны
запуска iOS, `og-image`, манифесты, разбор чужого `<head>`, сниппеты под
Next.js, проверка контраста, история правок. 8353 строки, работает на
`fi.equiply.ru`, сервера нет.

**Недостаёт одного: доступа для агента.** Всё перечисленное умеет только
человек, сидящий в браузере.

## I квартал (октябрь — декабрь 2026): ядро и MCP

**Цель:** агент делает набор иконок сам, без человека и без браузера.

| Шаг | Что именно |
|---|---|
| Ядро | вынести `renderer`, `ico`, `manifest`, `export`, `og-renderer`, `splash-renderer` в слой без React и DOM |
| Адаптер | две реализации canvas: браузерная и `@napi-rs/canvas` для Node |
| Сервер MCP | `make_icons` (SVG / эмодзи / текст → полный набор), `make_og_image`, `audit_head` |
| Сцепка | вызов из `project-template`: новый проект получает иконки одной командой |

**Проверка, а не ощущение:** попросить Claude завести проект из шаблона и
сделать ему иконки. Получилось без ручных правок — квартал закрыт.

**Развилка в конце квартала:** если за три месяца агент ни разу не позвал
инструмент в реальной работе — дальше не идти, вернуться к нему, когда появится
повод. Это относится ко всем кварталам ниже.

## II квартал (январь — март 2027): карточки соцсетей как отдельная вещь

**Почему это следующее.** `og-image` уже есть, но как одна картинка из иконки.
А нужна она **каждой странице**, и делается руками в фигме — это ровно та
работа, которая делается по правилам.

| Шаг | Что именно |
|---|---|
| Шаблоны карточек | заголовок + описание + логотип → 1200×630, несколько раскладок |
| Инструмент MCP | `make_og_image` принимает текст страницы, а не только иконку |
| Разбор | `audit_head` дополняется проверкой OG и Twitter-карточек, `robots.txt`, `sitemap.xml` |

**Проверка:** на своих сайтах карточки появляются без фигмы и без ручной правки.

## III квартал (апрель — июнь 2027): фирменный стиль из одного входа

**Замысел квартала:** дать на вход фирменный цвет и логотип — получить всё
остальное.

| Шаг | Что именно |
|---|---|
| Цветовые токены | из одного цвета — переменные CSS для светлой и тёмной темы; проверка контраста уже написана |
| Оптимизация картинок | PNG/JPEG → WebP/AVIF с выбором качества, в браузере |
| Пресеты проекта | сохранённый набор «цвет + шрифт + форма», чтобы у семейства сайтов был один вид |

**Проверка:** новый клиентский сайт получает иконки, карточки и тему из одного
описания, а не из семи разных мест.

## IV квартал (июль — сентябрь 2027): имя и форма

К этому моменту станет ясно, разросся проект или остался про иконки. Тогда и
решать:

- **Остался про иконки** — оставить `favimaker`, план закрыт, развивать
  дальше незачем.
- **Разросся** — переименовать (имя должно называть суть из первого раздела),
  и решить, остаётся ли это личным инструментом или становится продуктом.

Переименование **не делать раньше**: имя, выбранное под замысел, а не под
сделанное, придётся менять второй раз.

## Чего не делать весь год

**Серверной части.** Отсутствие сервера — свойство, а не упрощение: файл не
уходит с машины, приложение работает офлайн и не зависит от того, пропускают ли
трафик. Появится сервер — исчезнет главное отличие.

**Редактора изображений общего назначения.** Граница проходит по слову
«детерминированно»: раскладка иконки по правилам — да, художественная обработка
— нет.

**Огласки.** Решено сознательно: автор не видит в проекте того, о чём хочется
рассказывать. Если за год появится — вернуться к вопросу, но не раньше.

## Как пользоваться этим планом

Раз в квартал — один вопрос: **звали инструмент в работе или нет?** Ответ «нет»
два квартала подряд означает, что план пора закрывать, а не переписывать.

Это дешевле, чем выяснять то же самое через год по количеству несделанного.
